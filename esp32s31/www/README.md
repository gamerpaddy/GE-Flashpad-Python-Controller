# FlashPad ESP32-S31 web UI (`www/`)

Vanilla JS, no framework, no CDN, no external fonts - it works with the ESP32 offline. The ESP only stores and serves the raw
frame; **all pixel processing runs in a Web Worker in the browser**. Contract: [`../docs/API.md`](../docs/API.md) (unchanged).

| file | role |
|---|---|
| `index.html`, `app.css`, `app.js` | UI: status strip, Capture, X-ray safety, Dark, Settings, Log, viewer, processing sidebar, saves |
| `proc-core.js` | **pure** processing functions + the `Pipeline` class (UMD: worker, page and the Node tests all load this file) |
| `proc-worker.js` | worker shell: message queue, cancel, progress, exports |
| `palettes.js` | 9 exact cv2 LUTs (generated by `tools/gen_palettes.py`, do not edit) |
| `png16.js` | PNG encoder (16-bit gray / 8-bit RGB), `CompressionStream('deflate')` with a pure-JS stored-block fallback |

Gzipped total is about 51 KB (budget 150 KB). `proc-core.js` is an addition to the asset list in API.md ("Static assets");
`components/web_ui/CMakeLists.txt` already embeds everything in `www_gz/`, so nothing else is needed.

## Run / test / build

```bash
python tools/mock_esp_server.py --port 8080            # mock ESP: serves www/ and implements every API.md endpoint
python tools/mock_esp_server.py --gz --rate 3 --speed 2  # serve www_gz/ gzipped like the firmware; throttle /api/frame to 3 MB/s; 2x faster capture sequence
node --test tools/test                                  # 38 tests, Node 22, no npm; creates tools/test/fixtures/expected.json with Python on demand
python tools/build_www.py                               # www/ -> www_gz/*.gz + manifest.json (LF-normalised, deterministic)
python tools/gen_palettes.py                            # regenerate www/palettes.js (needs cv2)
```

The mock has synthetic frames (phantom + gradient + noise, the real panel's dead rows 48 / 1093 and column 783 at ~0 ADU, dark ~1789 ADU
with fixed pattern), the full capture state machine (`arming -> wait_window -> exposing -> readout -> receiving 0..2048 -> verifying
[-> saving_dark] -> done -> idle`), the X-ray master switch (auto-clears), relay timing, test pulse, abort, re-init, config, log and
validate-fast. `POST /mock/upload?name=` / `GET /mock/uploads` are mock-only helpers (not in the contract) used to test the save buttons.

## Processing chain (also in the UI under "Processing chain")

1. **Dark subtraction** - int32 subtract, clamp 0..65535, nothing added back (`_process`). Skipped without a dark, for a *dark-type* frame, on a size mismatch.
2. **Line repair** - `_bad_lines` / `build_defect_map` / `_interp_lines` / `apply_defect_map` exactly: per-line median, running-median baseline (+-16, truncated
   at the ends, even count = mean of the middle two), robust sigma = 1.4826*MAD (1.0 if MAD = 0), bad if `|dev|/sigma > threshold` (default 25) or line max = 0, first/last
   12 lines ignored, detection on the dark-subtracted frame OR'd with the dark, rows then columns, linear interpolation in float32, clip, truncate. Manual rows/columns join the list.
3. **Pixel repair** - manual pixels, then optional automatic hot/dead pixels. Runs *after* the lines (the README of the Python GUI warns that the other order smears the lines).
   Detection: `d = v - median(8 neighbours)`, `sigma = 1.4826*median|d|`, flag `|d| > thr*sigma` (default 12); repair = median of the *unflagged* 3x3 (else 5x5) neighbours.
4. **Destripe** (row/column median minus its +-N running median) -> **Flatten** (divide by a large Gaussian) -> **Denoise** (Gaussian / median 3x3, 5x5 / bilateral /
   non-local means) -> **Unsharp** -> **Local (multi-scale) contrast**. float32, each one bypassable (switching it off gives bit-identical output to the plain chain - tested). Rounded to u16.
5. **Rotate / flip** (quarter turns clockwise, then flip H, then flip V). This is the *processed 16-bit data* of the RAW-processed and PNG-16 saves.
6. **Window**: percentile autorange exactly as `to_u8` (rows 4..H-8 step 3 x all columns step 3 = 463,757 samples, `lo = s[int(n*lo)]`, `hi = s[min(n-1,int(n*hi))]`, defaults 1.0 % / 99.5 %,
   float32 arithmetic, truncation) or manual absolute lo/hi; optional gamma / log / sigmoid curve applied before the 8-bit quantisation.
7. **CLAHE** on the 8-bit window - **bit-exact with `cv2.createCLAHE(clip,(t,t)).apply`** (checked for 2048x2048, t in {2,4,8,16,32}, clip in {0.5,2,3.7,12}, and non-divisible sizes).
   A 12-bit variant (finer, **not** cv2) is selectable. -> **Invert** -> **Palette** = what is displayed and what "PNG display" contains.

Percentile range, CLAHE, invert and palette are applied to the whole frame and cropped afterwards, so a cropped save is a crop of the shown image.

### Findings worth knowing
* The float64 numpy recipe from the task description is **not** bit-exact with cv2 5.0.0: it differs on rounding ties (1 pixel of 49,152 on a probe image). OpenCV does the interpolation in
  float32; `claheCore` emulates that with `Math.fround` at every operation and matches cv2 on all tested images. (The LUT is float32 `sum*(255/area)`, rounded half-even.)
* The percentile ranks are computed from a 65,536-bin histogram of the sample set, which is identical to `np.sort` and much faster.
* `Pipeline.run` returns the same bytes as `flashpad_capture_gui.render_rgb(apply_defect_map(...))` for the default chain (hash-compared in `pipeline.test.mjs`).

## UI behaviour

* **Polling**: `/api/status` about every 250 ms (an overlapping request never starts). When `frame.seq` changes the frame is fetched with a progress bar (`ReadableStream`), its CRC32 is
  checked against `X-Frame-Crc32`, and it is reprocessed. The stored dark is fetched when `dark.crc32 / window_ticks / scrubs` change (not while `dark.saving`). Missing frame headers fall back to `status.frame`.
* **Dark** source: *Stored dark (device)* (default), *Local dark* (any frame picked in the browser; a newly captured DARK frame is adopted automatically), *None*. The "stored dark window != entered window"
  warning is shown in the Capture panel, the Dark panel and under the viewer.
* **Safety**: the master switch shows the *device* state only; enabling asks for confirmation (default button = Cancel). When enabled the header pill, the panel and the page edge turn red. Test pulse and
  (optionally, on by default) every X-ray capture while enabled ask for confirmation. Abort never asks.
* **Rendering**: slider drags run a reduced-resolution preview (1/2..1/8, chosen from the viewport, spatial parameters scaled) with at most one job in flight; the full-resolution result replaces it when
  the slider settles. Heavy filters yield every ~30 ms: a newer request supersedes them and the spinner's **Cancel** button reverts the settings to the last completed render. NLM at 2048x2048 takes ~2 s (search 3, patch 1).
* **Viewer**: wheel zoom about the cursor (x1.25 per tick, 0.05..40), nearest neighbour from 1.5x, bilinear below; drag pan; pinch on touch; arrow keys / `+` `-` `0` `1` on the focused canvas. Tools: Pan, ROI (mean / SD / SNR),
  Profile, Crop (draggable box, default `[204,204,1844,1844]`, "Full frame" button), Mark (click a pixel / row / column to add it to the manual defect list, stored in sensor coordinates). Cursor readout shows x, y, raw and processed value.
* **Saves** (names use the time the frame was received, e.g. `flashpad_xray_20261113_153129_raw.raw`): RAW original (the received bytes, never cropped), RAW processed (u16 LE), PNG display (8-bit RGB), PNG 16-bit gray (processed data).
  With "Apply crop box" ticked the last three are cropped and get a `_WxH` suffix. Settings are kept in `localStorage`.

## What was verified (and how)

* `node --test tools/test` - 38 tests, ~9 s: every function against the Python reference (`make_fixtures.py` imports `flashpad_capture_gui` and cv2/numpy; test frames are regenerated from an integer hash on both sides, only
  hashes and small arrays are stored). Exact: dark, `_bad_lines`, defect map/repair, `to_u8`, CLAHE, palettes, median, geometry, whole pipeline vs `render_rgb`, single-pixel repair. Numerically close (documented tolerances): Gaussian,
  bilateral and NLM (exp LUT), unsharp, local contrast, destripe, large-sigma blur / flatten. PNG files are decoded with Pillow (both compressors).
* Browser pane against the mock server: capture DARK and X-RAY end to end (state strip, relay timing, auto-load, auto dark), every processing control driven through the DOM (all bypasses return to the baseline image),
  preview/full switching, NLM progress + cancel, ROI / profile / crop / mark / histogram-handle drags with real mouse events, safety dialogs, abort, re-init, settings save/reload, validate-fast, log, light/dark theme,
  375 px phone layout without horizontal scroll, gzip serving. **All four save buttons** were run (with and without a non-square crop box); `tools/test/verify_saves.py` then confirmed with Pillow/numpy: RAW original == `/api/frame`,
  RAW processed == the Python chain, PNG-16 == processed data, PNG display == `render_rgb` (Viridis + CLAHE 16 tiles + invert) - all with 0 differing pixels.

Browser test recipe for the saves (what was used): in the page console install a hook that uploads every `<a download>` blob to `/mock/upload?name=...`, press the four Save buttons, then run
`python tools/test/verify_saves.py --server http://127.0.0.1:8080 --dir <upload dir> --params '{"loPct":0.5,"hiPct":99.9,"clahe":true,"clip":3,"tiles":16,"palette":"Viridis","invert":true}' [--crop x0,y0,x1,y1]`
(valid for the default chain: no denoise / enhancement / orientation, because the reference is the Python code).

## Not verified / limits

* Touch pinch-zoom / two-finger gestures and the middle-mouse pan are implemented but were not exercised (no touch device in the Browser pane); screen-reader behaviour was not tested (controls are native elements with labels, canvas keyboard controls were).
* Not run against the real ESP32 firmware or over Wi-Fi (only the mock). The Browser pane is Chromium; Firefox / Safari are untested (`CompressionStream` falls back to stored PNG blocks if missing).
* Memory: raw + dark (each copied to the worker) + three float32 stage caches + RGBA is roughly 150-200 MB at 2048x2048. Fine on a laptop; a low-RAM phone may struggle with Local contrast + NLM together.
* The viewer canvas captures the wheel and (touch) swipes; scroll the page from outside the canvas.
* `SharedArrayBuffer` is not used (it would need COOP/COEP headers from the ESP), so frames are copied once into the worker.
* Little-endian host assumed for the `Uint16Array` view of the frame (all browsers in practice).

## Proposed changes to `docs/API.md` (none are required)

1. Static assets: add `/proc-core.js` (already embedded by the CMake glob).
2. `GET /api/frame` while a capture is receiving: respond 404/409 with JSON; the UI just retries after 2.5 s. Keeping `X-Frame-Seq` on the response lets the UI detect a frame replaced mid-download.
3. `X-Frame-Crc32` should be the CRC-32 (IEEE, zlib) of the 8,388,608 body bytes - the UI warns on mismatch.
4. `capture.state` may stay `done` until the next capture; the UI treats `idle | done | error | aborted` as "not running".
